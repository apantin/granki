# Изменения

Здесь записаны заметные изменения в каждой версии. Версии нумеруются по [SemVer](https://semver.org/lang/ru/), порядок выпуска — в [release.md](docs/dev/release.md).

Новые изменения дописываются в раздел «Не выпущено» сверху. При выпуске раздел получает номер версии и дату. Если изменение несовместимо со статьями прошлой версии, рядом пишется, что сделать при обновлении.

## 0.1.0 — не выпущена

Первая версия.

- 9 скиллов: агент «Главред», серия, интервью и материалы, план статьи, раздел, ревью, публикация, редактура, скрипты.
- 11 скриптов: проверка статьи и серии, таблица утверждений, статусы плана, журнал находок, сводка серии, оценка последствий изменений, сборка канона, комнаты, сборка HTML.
- 5 комнат для обсуждений с ролями агентов на основе `bmad-party-mode`.
- Канон — редакционные правила в трёх слоях: проект, серия, статья. Названия разделов задаёт шаблон Granki; `canon.py` предупреждает, если `(+)` или `(-)` не находят раздел в верхних слоях.
- Журнал статьи и серии: реестр находок и хронология. Отложенные находки находятся в следующей сессии.
- Справка о конфликтах с другими наборами скиллов и о том, как отключить их в проекте в популярных средах.
- Туториал на вымышленной серии `docs/example/bread/`. Его команды прогоняет тест.

По итогам пилота на вымышленных сериях ([pilot.md](docs/dev/pilot.md)):

- Таблица утверждений: агрегаты по строкам CSV (`agg=count|sum|mean|median|min|max`, условия с вариантами `a=x|y`) и выражения над другими утверждениями (`expr: R-a / R-b - 1`) сверяются скриптом. Раньше медианы и доли из сырого журнала приходилось писать `derived:`, и их никто не сверял.
- `check.py`: даты в тексте не требуют утверждений при `integers: true` (`numbers.dates: true` возвращает проверку); проверка `headings` — первый заголовок равен `title` плана; `--plan` работает до первого раздела; `--section` принимает путь.
- `journal.py set --status applied` предупреждает, если цитата «Было» осталась в тексте.
- `plan.py`: план статьи не утверждается, пока план серии в `draft` (или `--force`).
- `build_html.py`: внешние ресурсы в сыром HTML отсекаются до Pandoc: Pandoc 3.6 сам скачивал их и встраивал.
- Разговор с автором ([dialog.md](skills/granki-tools/references/dialog.md)): без внутренней кухни, один вопрос по смыслу, мелочи списком с решением по умолчанию, вопросы о фактах без готовых ответов, в кавычках только дословные слова автора.
- Решение по находкам: три группы, правки формы пакетом, однотипные правки одной находкой; на уровне статьи редактура ищет только то, что видно на уровне статьи.
- Проход голоса — последний шаг ревью статьи: предложения «было → стало» там, где автор сказал бы живее.
- Письмо раздела: правила письма читаются до черновика; переход в плане — связь мыслей, а не готовая фраза; оговорка звучит полностью один раз; ограничения — один раз и рядом с числом; читателю нужен ответ с условиями; голос — не только запреты; новые подсчёты — проверяемыми выражениями.
- `plan.py publish` не публикует раздел, который не принят или изменён после приёмки.

Как собиралась и проверялась версия — в [history.md](docs/dev/history.md).
