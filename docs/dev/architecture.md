# Устройство модуля

Из чего состоит Granki и что из этого уже сделано. Процесс описан в [process.md](../user/process.md), точные форматы файлов — в [formats.md](../../skills/granki-tools/references/formats.md).

Код модуля и префикс скиллов — `granki`. Префикс `bmad-` зарезервирован за официальными скиллами BMad. Правила товарного знака запрещают слово BMad в названии, а в описании допускают «Compatible with BMad Method v6».

## Слои и установка

```
Слой 1  BMad Method v6.12 core (не меняем):  bmad-party-mode · bmad-review · bmad-help · bmad-advanced-elicitation
Слой 2  модуль granki:                       агент «Главред» · скиллы процесса · granki-editorial · granki-tools (скрипты, шаблоны, комнаты)
```

Установщик BMad принимает модуль через `--custom-source`: Git URL или локальный путь. Есть два режима: по `.claude-plugin/marketplace.json` или прямой обход папки со скиллами. Файлы `module.yaml` и `module-help.csv` ищутся в общей родительской папке скиллов.

Проверено на 6.12.4 ([ADR 0001](decisions/0001-bmad-v6-foundation.md)). Команда `npx bmad-method@6.12.4 install --modules core --custom-source <путь> --tools claude-code,codex` ставит:
- ядро и все 9 скиллов Granki в `.claude/skills` и `.agents/skills`;
- справку `bmad-help` с этапами Granki;
- настройки модуля в `_bmad/granki/`.

После этого `rooms.py install` добавляет составы комнат в `_bmad/custom/bmad-party-mode.toml`, и все 5 комнат разбираются `resolve_party.py` из BMad.

В проекте-пользователе стоит коммитить `_bmad/custom/*.toml`, кроме `*.user.toml`. Установленные скиллы и скрипты BMad воспроизводит установщик.

## Раскладка репозитория

```
granki/
  .claude-plugin/marketplace.json   плагин granki и список скиллов; по нему установщик BMad находит модуль
  skills/
    module.yaml  module-help.csv    код модуля и этапы для bmad-help (phase, preceded-by, followed-by)
    granki-agent-editor/            Главред: SKILL.md + customize.toml с персоной и меню
    granki-series/  granki-intake/  granki-article-plan/  granki-section/
    granki-review/                  + references/decisions.md и references/lenses/*.md
    granki-publish/
    granki-editorial/               + references/passes, writing, genre-experiment.md, voice.md; NOTICE.md
    granki-tools/                   scripts/ (+ tests/), references/formats.md,
                                    assets/templates/, assets/party-rooms.toml, assets/article.template.html
  docs/user/                        для пользователя: туториал, процесс, роли, конфликты с другими скиллами
  docs/dev/                         для разработчика: порядок изменений и выпуска, замысел, устройство, решения, история
  docs/example/                     примеры: HTML-статьи пилота; bread/ — вымышленная серия для туториала
  README.md  CHANGELOG.md  LICENSE
```

Скиллы обращаются к скриптам соседнего скилла по пути `{skill-root}/../granki-tools/scripts/`: все скиллы модуля ставятся в одну папку.

## Агент и скиллы

| Компонент | Назначение |
|---|---|
| `granki-agent-editor` «Главред» | Состояние серии, нерешённые находки, следующий шаг, комнаты. Меню: ST, SE, IN, PL, SC, RV, ED, PB, PT |
| `granki-series` | План серии, состав статей, изменения на несколько статей, статус и ревью серии |
| `granki-intake` | Интервью автора, материалы, таблица утверждений, тезисы, сверка утверждений автора |
| `granki-article-plan` | План статьи: черновик, обсуждение, ревью агентами, утверждение, перестройка, восстановление плана по готовому тексту |
| `granki-section` | Раздел: написать, разобрать замечания автора, принять |
| `granki-review` | Ревью раздела, статьи или серии: скрипт, независимые линзы, комнаты, решение по находкам |
| `granki-publish` | HTML, проверка перед публикацией, отметка публикации, новая версия |
| `granki-editorial` | Проход редактуры, правила письма, голос автора и канон |
| `granki-tools` | Скрипты, шаблоны, составы комнат |

Скиллы следуют стандарту bmad-builder: описывают результат, а не шаги; `SKILL.md` короткий, подробности — в `references/` на один уровень; детерминированная работа вынесена в скрипты.

## Скрипты

Скрипты — Python 3.11+ с зависимостями по PEP 723, запуск через `uv run`. Каждый печатает JSON и возвращает код: 0 — прошло, 1 — проверка не прошла, 2 — ошибка входа.

| Скрипт | Что делает |
|---|---|
| `check.py --plan … [--section …]` или `--series …` | Объём, трассировка чисел прозы до утверждений, актуальность утверждений, оговорки, ссылки, публичность, рисунки, блокировка опубликованного |
| `claims.py build\|verify` | Таблица утверждений по правилам `claims_build` и сверка с источником |
| `plan.py` | Статусы статьи и разделов по жизненному циклу, публикация, новая версия |
| `journal.py` | Журнал: реестр находок, решения, хронология, нерешённые находки серии |
| `status.py` | Серия → статья → раздел: статусы, хеши, устаревшие ревью, нерешённые находки |
| `impact.py` | Какие разделы задевает изменение; варианты по статусу статьи. Только читает |
| `canon.py` | Канон из слоёв проекта, серии и статьи |
| `rooms.py` | Составы комнат в настройки party mode проекта |
| `build_html.py --series\|--plan` | Автономный HTML статей и указатель со сверкой с источником |

Обязательная оговорка помечается в тексте как `<!-- caveat:C4 -->`, и скрипт ищет метку, а не формулировку. Для текстов без меток есть запасной поиск по регулярному выражению `pattern`. Лимиты и обязательные оговорки задаются во фронтматтере плана, а не в коде.

## Раскладка артефактов серии

```
<серия>/
  series-plan.md                    план серии; known_divergences и раздел «Принятые расхождения»
  journal.md                        журнал серии: хронология, изменения на несколько статей, находки ревью серии
  author-notes.md                   то, что знает только автор: [автор], [проверить], [подтверждено], [расхождение]
  canon.md                          слой канона серии (необязательно)
  shared/evidence/                  опись материалов с SHA, тезисы
  reviews/series-*.md
  NN-slug/
    plan.md                         план статьи; фронтматтер: статус, версии, разделы, хеши
    canon.md                        слой канона статьи (необязательно)
    sections/00-intro.md …          реализация
    journal.md                      реестр находок и хронология действий
    reviews/section-*.md  article-*.md
    assets/ data/ evidence/
```

Если тексты статьи лежат в другом месте (перенос готовой статьи), в плане задаётся `root:`. Журнал и ревью при этом остаются рядом с `plan.md`.

## Редакторское знание: `granki-editorial`

Источник — [redaktura-skills](https://github.com/N1arko/redaktura-skills) на коммите `d1ebaff`, лицензия CC BY 4.0.

| Взято | Откуда | Зачем |
|---|---|---|
| Смысл и фактура, структура, тональность, предложение, слово, ритм, следы нейросети, оценки, штампы | `redaktura/references` | Проходы редактуры |
| Бриф, фактура, организация, драматургия, оформление | `statya/references` | Правила плана статьи и письма раздела |
| Вопросы интервью | `redpolitika/references/interview.md` | Первичная настройка голоса (`voice.md`) |
| Не взято: посты, промо, UX, «продукт в тексте» | — | Не жанр Granki |

14 справочников скопированы почти без изменений: правки затронули 3 файла и 12 строк. Список изменений — в [NOTICE.md](../../skills/granki-editorial/NOTICE.md), его соответствие проверено `diff`. Новые файлы: `genre-experiment.md` (жанр «обзор результатов эксперимента»), `voice.md` (голос автора и слои канона), `SKILL.md`. Плагин redaktura может оставаться установленным для других задач, но Granki на него не опирается.
