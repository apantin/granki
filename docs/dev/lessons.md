# Уроки первой серии

Granki вырос из подготовки первой серии автора — четырёх статей с обзором результатов эксперимента по сравнению моделей. Серия писалась по карточкам задач с разовым применением скиллов `statya` и `redaktura`. Источник уроков — переписка с агентами Codex и Claude Code за три дня работы над серией. Ниже — выводы без пересказа переписки и без материалов серии.

## Что сработало

| Практика | Свидетельство | Куда в процессе |
|---|---|---|
| Критическое ревью замысла по данным до написания текста | Два независимых ревью замысла (одно — пятью линзами) нашли выбор настроек на тех же текстах, на которых шло сравнение, несовпадение рецептов между выборками, недостаточность одной метрики, большой вес синтетических данных и перевёрнутый тезис одной из статей | Обсуждение плана серии, «Совет по находкам» |
| Числа проверяют скрипты | Таблица утверждений `R0001…`, сверка сотен ячеек и чисел, сравнение набора чисел до и после редактуры | `claims.py`, `check.py` |
| Решения по одному вопросу с вариантами и рекомендацией | Прямые просьбы автора | Правила работы с автором |
| Работа по карточке задачи одной командой, коммит и сборка только по команде | Повторяющийся шаблон запроса «выполни задачу …, без коммита» | Правила работы с автором |
| Разделы статьи в отдельных файлах с `assets/`, `data/`, `evidence/` | Перестройка статей по просьбе автора | Раскладка артефактов, цикл раздела |

## Что переделывали

| Что произошло | Пример | Требование |
|---|---|---|
| Агент не знал того, что знает только автор | Около половины комментариев к первой статье: формат ответа модели, зачем синтетика, почему выбран этот подход, рабочий контекст, железо, «не претендую на научность», почему разные режимы | Интервью автора до планов, `author-notes.md` |
| Факты о собственной работе автора додумывались | Субагенты пометили эталон как не проверенный человеком, хотя автор проверял его лично, а консервативная метка стояла намеренно | Факты о работе автора — только от автора |
| Утверждения автора не всегда совпадали с журналами | Автор по памяти назвал не ту версию модели-генератора и не упомянул режим ускорения у одной из моделей | Утверждения автора тоже сверяются с источником, расхождение выносится к автору |
| Редактура вносила чужой голос | «интервал включает ноль» (автор: «я так не говорю»), привязка к периоду в лиде, телеграфный стиль из-за жёсткого лимита знаков | Линза и роль «Голос автора», ориентировочный объём, список «как я говорю и не говорю» |
| Рисунки правились несколько раз | Числа на графиках просили дважды, кэш показывал старую картинку; подписи, размеры моделей, заголовок на картинке, две разные машины на одной шкале | Требования к рисункам в плане, проверка отрисованного файла, новое имя файла |
| Некорректные или лишние сравнения | Модели разной архитектуры в одном ряду, лишняя колонка стоимости, путаница выборок разного размера при сверке | Линзы «свежий читатель» и оверклейм, подпись выборки у чисел |
| Хрупкие проверки | Скрипты держали жёсткий лимит знаков и искали дословную фразу оговорки; три почти одинаковых скрипта; PDF не собирался на Linux из-за шрифта macOS | Один `check.py` с настройками из плана, метки оговорок по ID |
| Серия менялась на ходу | Новая статья появилась из чтения первой; итоговая сверка серии не проводилась | Перестройка плана серии, запрос на изменение, ревью серии |
| Ревью целой статьи тяжело для автора | Пакеты из 18 и 7 комментариев к одной статье | Работа по разделам, принятие каждого раздела |

## Урок PaperOrchestra

[PaperOrchestra](https://github.com/google-research/paper-orchestra) оптимизирует статью под оценку LLM-рецензентом. Без программной сверки чисел с данными такая оптимизация ненадёжна: рецензент-модель не видит расхождений в сотнях значений. Отсюда правило Granki: числа проверяют скрипты, агенты проверяют смысл.
