# Granki: проверки и сборка

Ты запускаешь скрипты и объясняешь результат автору. Скрипты отвечают за всё, у чего есть один правильный ответ: совпадают ли числа с источником, на месте ли оговорки, не изменился ли опубликованный текст. Не пересчитывай числа сам и не исправляй отчёт скрипта на глаз. Форматы файлов описаны в `{skill-root}/references/formats.md`; читай его, когда план или серия не проходят разбор.

Запуск: `uv run {skill-root}/scripts/<скрипт>.py …`. Скрипты печатают JSON; `status.py --format md` и `canon.py` без `--format json` печатают Markdown. Код выхода 0 — всё прошло, 1 — есть проваленные проверки (`check.py`, `claims.py verify`, `build_html.py`), 2 — ошибка входа или конфигурации, причина в поле `reason`. Предупреждения (`warnings` в отчёте `check.py`) проверку не проваливают.

| Задача | Команда |
|---|---|
| Проверить раздел | `check.py --plan <статья>/plan.md --section <файл>` |
| Проверить статью | `check.py --plan <статья>/plan.md` |
| Проверить серию | `check.py --series series-plan.md` |
| Следы нейротекста | `style.py --plan <статья>/plan.md [--section <файл>]` или `style.py --file <файл.md>` |
| Статус серии | `status.py --series series-plan.md --format md` |
| Что затронет изменение | `impact.py --series series-plan.md` и любое из: `--claim <ID>`, `--term <regex>`, `--section <статья>/<файл>` (каждое можно повторять) |
| Собранный канон | `canon.py --series series-plan.md --article <папка>`: проект → серия → статья |
| Записать действие в журнал статьи | `journal.py log --journal <статья>/journal.md --actor агент\|автор --action "…" [--target <файл>]` |
| Добавить находки ревью в журнал | `journal.py add --journal <статья>/journal.md --source <файл ревью> --findings <находки.json>` |
| Решение по находкам | `journal.py set --journal <статья>/journal.md --id N001,N002 --status applied\|rejected\|deferred\|open [--note …] [--actor автор]` |
| Нерешённые находки во всей серии | `journal.py list --series series-plan.md` |
| Записать раздел в план | `plan.py entry --plan … --file NN-имя.md [--caveats C1] [--claims R1,R2] [--after <файл>]` |
| Статус плана серии | `plan.py series --series series-plan.md --set draft\|approved\|writing\|done [--actor автор]` |
| Статус статьи или раздела | `plan.py status --plan … --set <статус>`; `plan.py section --plan … --file … --set accepted\|drafted\|needs-rework\|…`; `plan.py sync` — добавить новые файлы разделов в план |
| Публикация и новая версия | `plan.py publish --plan … [--url …] [--date …] [--html <собранная страница>]`; `plan.py revise --plan …` |
| Комнаты для обсуждений | `rooms.py status\|install --project-root <проект>` |
| Таблица утверждений | `claims.py build --plan <статья>/plan.md` (по правилам `claims_build`) или `claims.py verify --plan <статья>/plan.md` |
| HTML | `build_html.py --series series-plan.md --output <папка>`; нужен Pandoc (`GRANKI_PANDOC` или `--pandoc`) |

Как читать результат:

- **`numbers.untraced`** — число в тексте, которого нет в таблице утверждений. Либо в тексте опечатка, либо утверждение не заведено. Спроси автора, если не очевидно, что из двух.
- **`claims.drift`** — утверждение разошлось с исходной таблицей. Значит, изменились данные или утверждение устарело. Текст по нему не правь, пока автор не решит, что верно.
- **`claims.unverifiable`** — утверждения `derived:`: их скрипт сверить не может. Назови их автору, если раздел на них опирается. Если значение — число строк, медиана, сумма или отношение других утверждений, перепиши источник агрегатом или `expr:` (formats.md), и скрипт будет его пересчитывать.
- **`published-lock`** — правка опубликованной статьи. Править можно только после перевода статьи в `revising` по решению автора.
- **`journal.py list`** — нерешённые находки (`open`, `deferred`). `still_present: false` значит, что цитаты из «Было» в разделе уже нет: показывай такую находку автору, не применяй.
- **`journal.py set --status applied`** с `warnings` — цитата из «Было» всё ещё в тексте. Скорее всего, правка не прошла: проверь файл и поправь статус.
- **`style.py`** только подсказывает, код выхода 0. В `signals` — сработавшие ориентиры по текстам пилота, не нормы; в `matches` — цитата, файл и «абз. N» от заголовка. Решает агент: ограничение вывода и обязательная оговорка (`caveat` в совпадении) — не дефект.
- **`impact.py`** ничего не меняет. Для неопубликованных статей вариант один — доработка разделов. Для опубликованных автор выбирает: новая версия, записанное расхождение или без изменений.

HTML собирай только по прямой просьбе автора.
